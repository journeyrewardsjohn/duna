# Definition of done

Dated 27 November 2026 (work package Q0). Every work package in
[`web-hq-backend.md`](web-hq-backend.md) and [`mobile.md`](mobile.md) meets
this list **before its pull request is opened**. Each line is a statement a
reviewer can answer yes or no, followed by how to prove it. If a line cannot be
met, say so in the PR under "Follow-ups" with the reason; never delete the line
from your checklist.

Order of authority is unchanged: [`AGENTS.md`](../../AGENTS.md) safety, money,
health-data and confirmation rules, then the contract in
[`docs/design/tideline-4.1.1/`](../design/tideline-4.1.1/README.md) (rules
R1–R22), then this file. The journeys every package feeds are in
[`persona-journeys.md`](persona-journeys.md).

No local look-alike.                                                                                                                       | Diff shows no new button, field, dialog, sheet, toast, chip, loader or empty-state markup outside `packages/ui`.                                                                                 |

## 2. Every state is designed and reachable

A page or pane is not done until **each** state below exists, is designed from
a board or the contract, and can be shown in demo mode or a test.

| #    | State                       | Statement                                                                                                                                                                                                                | How to prove it                                                                                                         |
| ---- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 2.1  | Loading                     | The brand loader (`PageLoader`, Rally loader) or a `Skeleton` with the final layout's geometry; nothing shows before 250 ms (`LOADING_DELAY_MS`), and once shown it stays 400 ms (`LOADING_MIN_MS`). Never a blank area. | Component test with a pending promise; persona suite `expectNoLayoutShift` (cumulative layout shift under 0.1 on load). |
| 2.2  | Empty                       | A title, one line and **one next action** (`EmptyState` / `FirstLight`). Never `0/0`, `0–0` or an empty table.                                                                                                           | Demo fixture or test with an empty list renders the action.                                                             |
| 2.3  | Error                       | Says what happened, what to do, and offers Retry; keeps the last good data visible (dimmed) where it had some. Shows the request id in a "Details" disclosure.                                                           | Test that rejects the query; Retry calls it again.                                                                      |
| 2.4  | Offline or degraded         | Says the data may be out of date and when it was last fresh; writes queue or are refused with a reason, never silently lost.                                                                                             | Playwright `context.setOffline(true)` (web); airplane mode in the simulator (native).                                   |
| 2.5  | Partial data                | Missing values say "Pending" or "Not set", never zero; the rest of the page still works.                                                                                                                                 | Fixture with optional fields removed.                                                                                   |
| 2.6  | Permission denied           | A person without the scope sees why and who can grant it, not a crash or an empty page; the server refuses too.                                                                                                          | Persona suite as `coach` or `player` opening an owner page; router test with a scope-less actor.                        |
| 2.7  | Feature switched off        | With the kill switch off the feature hides or explains itself; nothing half-renders.                                                                                                                                     | Unit test with `isFeatureEnabled` returning false; screenshot.                                                          |
| 2.8  | Provider not configured yet | An honest "not configured yet" state, no outbound call, no invented data; in Stripe test mode a visible "Test mode" label.                                                                                               | Test asserts no provider `fetch` while `providerStatus()` is `not-configured`; demo-mode screenshot.                    |
| 2.9  | Success                     | The result is visible where the person is looking (inline, toast or navigation) and names what happened ("Booking confirmed for Sat 10:30 AM").                                                                          | Persona journey step asserts the success text.                                                                          |
| 2.10 | Demo branch                 | Every new route opens in demo mode and every new procedure has a `usesDemoData()` branch with fixtures in `packages/core/src/demo/<domain>.ts`, parsed by its contract in a unit test.                                   | Persona suite opens the route; fixture parse test.                                                                      |

## 3. Motion

| #   | Statement                                                                                                                                                                                                                                                                                                                                                                                                                                  | How to prove it                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | Only three verbs: **Rise** (something grows out of a line, entering; 600 ms, `cubic-bezier(.2,.8,.2,1)`), **Rally** (the same move per item, 120 ms apart; a state change in place or a list arriving), **Cross** (travel over a line between views; 320 ms).                                                                                                                                                                              | Durations and easings reference `--td-duration-*` / `--td-ease-*` (or the native motion module); no literal `ms` or bezier in product code. |
| 3.2 | Nothing bounces, springs, overshoots or scales on hover. Press feedback is the token press (80 ms). Entrances play once; only loaders and the live indicator loop.                                                                                                                                                                                                                                                                         | `rg -n "spring\|bounce\|overshoot\|:hover[^{]*\{[^}]*scale" <your paths>` is empty.                                                         |
| 3.3 | Every animation has a reduced-motion equivalent: the end state, with at most a 200 ms fade.                                                                                                                                                                                                                                                                                                                                                | Screenshot with `reducedMotion: "reduce"` (Playwright `page.emulateMedia`) or the simulator setting; nothing moves but a fade.              |
| 3.4 | No animation blocks input: controls are usable during and after a transition; nothing waits for an animation to finish before accepting a tap.                                                                                                                                                                                                                                                                                             | Playwright clicks immediately after navigation; no `pointer-events: none` held for a transition's length.                                   |
| 3.5 | **Expected:** page and pane transitions (Cross, via `withViewTransition`); sheets and dialogs open and close (Rise from the edge, token `sheet` 260 ms); list insert and remove (Rally on first load, a short Rise for an insert, a fade for a remove); a score changing (Rally on the changed digit); a booking or payment confirmed (Rise of the confirmation); loaders (Rally loader, Crossing for search, Set by set for known steps). | Board names in the PR beside a short screen recording for each motion you add.                                                              |
| 3.6 | **Forbidden:** motion on scroll (lists never re-Rally on scroll); parallax or autoplay that carries content; animating layout properties (`width`, `height`, `top`) when `transform` or `opacity` would do; motion on money amounts or ratings before the data is final; any loop other than loaders and live.                                                                                                                             | Review of the diff; `rg -n "animation-iteration-count: infinite" <your paths>` only on loaders/live.                                        |

## 4. Feedback and confirmations

| #   | Statement                                                                                                                                                                                                                                                                                                                                                                                                                          | How to prove it                                                                                        |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 4.1 | Every action acknowledges within **100 ms** (pressed state from the component), shows progress if it takes longer than about **400 ms** (button loading state or `TopProgress`, via `useDelayedLoading`), and **ends in a visible result**: inline, toast or navigation.                                                                                                                                                           | Persona journey waits for the result text; component test with a slow promise shows the loading state. |
| 4.2 | A reversible action offers **Undo** in its toast (`useOptimisticAction` messages) for at least 5 s, and Undo really reverses on the server.                                                                                                                                                                                                                                                                                        | Test presses Undo and asserts the server state.                                                        |
| 4.3 | **Tier 0, no confirm:** reversible and low stakes (rename, reorder, toggle a preference, archive, mark read). Act at once and offer Undo.                                                                                                                                                                                                                                                                                          | No dialog appears; Undo toast appears.                                                                 |
| 4.4 | **Tier 1, confirm:** irreversible or outward-facing: sends a message, publishes, invites, cancels something that notifies people, changes what the public sees. One dialog that names the action and its audience ("Send to 14 people by email"), with the verb on the button ("Send to 14 people"), never "OK".                                                                                                                   | Persona helper `confirm("confirm", …)`; agent test shows the step refused without `allow`.             |
| 4.5 | **Tier 2, strong confirm:** money movement (charge, refund, payout, transfer), deleting data, or anything affecting many people (bulk cancel, roster-wide change). The dialog restates the **amount with currency, the recipients or count, and the consequence** ("Refund $48.00 to Jane Doe. Jane is emailed. This cannot be undone."). **Typed confirmation** (type the club or object name) only for destructive bulk actions. | Persona helper `confirm("strong", …)` asserts amount and recipient text are in the dialog.             |
| 4.6 | Never two modals deep: a confirm never opens from inside another dialog or sheet; close the first or confirm inline in it.                                                                                                                                                                                                                                                                                                         | Persona helper fails if a second `dialog` opens while one is open.                                     |
| 4.7 | AI proposes, a person confirms: Ask Duna and Concierge changes arrive as a `ProposalCard` (before / after) and pass through the same tier as the person's own action.                                                                                                                                                                                                                                                              | S4 test "nothing is written without confirmation".                                                     |

## 5. Input discipline

| #   | Statement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | How to prove it                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5.1 | Search and typeahead are **debounced at 220 ms** (`SEARCH_DEBOUNCE_MS`, `--td-debounce-search`) with `useAsyncSearch`/`createAsyncSearch`; Enter searches at once. Use **throttle** (not debounce) for continuous signals that must keep flowing: map pan/zoom bounds (one request per 300 ms while moving, plus one on settle), scroll position, resize, live-score typing indicators.                                                                                                                                                                                                                                                                                                               | Unit test with fake timers; persona suite sees one request per pause, not per keystroke.                                                                       |
| 5.2 | Stale requests are cancelled (`AbortSignal`) and late answers ignored, so results never arrive out of order; previous results stay visible, dimmed, while the next load runs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | `createAsyncSearch` tests cover this; for other lists, a test resolving two requests in reverse order.                                                         |
| 5.3 | Submits are **single-flight**: the button disables and shows progress on the first press, and a double click or double tap can never create two bookings, payments or messages.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | The persona suite's automatic duplicate-mutation check (the same method, path and body twice within 1.5 s fails the journey); unit test of the submit handler. |
| 5.4 | Every mutation that **creates money movement, a message or a booking** sends an **idempotency key** generated once per intent (when the form opens or the person first presses), reused on retry. The server already supports it: `runIdempotentMutation({ key: input.idempotencyKey, … })` in `packages/api/src/router.ts` (input field `idempotencyKey: z.string().uuid()`), `clientMessageId` on messaging sends (`messaging-router.ts`), and the `idempotencyKey` inputs of `court-checkout.ts`, `catalog-checkout.ts`, `catalog-session-bookings.ts`, `commerce.ts` and `family-wallet.ts`. New procedures of these kinds take `idempotencyKey` and wrap their write in `runIdempotentMutation`. | Router test: two calls with one key produce one row; client test: a retry reuses the key.                                                                      |
| 5.5 | **Optimistic** updates only where there is a rollback path **and** a message (`useOptimisticAction` with `messages.error`); never for money, sends or anything another person sees first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Test rejects the commit and asserts rollback plus the error toast.                                                                                             |
| 5.6 | Long forms (more than one screen, or more than about 8 fields) **autosave a draft** at most every 2 s after typing stops and on blur, say "Saved" quietly, and a **dirty-state guard** asks before leaving with unsaved changes (route change, close, back).                                                                                                                                                                                                                                                                                                                                                                                                                                          | Test: edit, navigate away, the guard appears; reload restores the draft.                                                                                       |
| 5.7 | Validation runs **on blur and on submit**, not on every keystroke (except clearing an error once fixed). Server errors are **mapped to their fields**; a form-level error says what to do. Focus moves to the first invalid field on submit.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Component test submits empty required fields and a server error with a `path`.                                                                                 |
