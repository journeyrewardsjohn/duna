# Building the Duna iOS apps locally

This covers Duna (`apps/player`, with its Apple Watch app) and Duna Pro
(`apps/pro`). Both apps use continuous native generation: the `ios/` folders
are generated by `expo prebuild` and are not committed.

## Toolchain

| Item            | Version                                           |
| --------------- | ------------------------------------------------- |
| Expo SDK        | 58 (`expo` 58.1.x)                                |
| React Native    | 0.88.1                                            |
| React           | 19.3.0 (Expo's pin)                               |
| Xcode           | 27.2 (27B52), iOS 27.2 SDK                        |
| iOS minimum     | 26.0 for both apps (`expo-build-properties`)      |
| watchOS minimum | 10.0 (Watch target, unchanged)                    |
| CocoaPods       | 1.17                                              |
| Node / pnpm     | Node 22.18+ or 24, pnpm 11.9                      |
| EAS build image | `macos-tahoe-26.6-xcode-27.2` (set in `eas.json`) |

App version is 2.0.0 in both apps. The update runtime policy is
`appVersion`, so 2.0.0 is a new over-the-air runtime: never publish an update
to it before the 2.0.0 binaries are on TestFlight.

The apps build with the UIKit scene life cycle (SDK 58 generates
`SceneDelegate.swift` and `UIApplicationSceneManifest`). They are universal
(`supportsTablet`) and resizable: nothing opts out of resizing, and
`pnpm verify:mobile-runtime` fails if a change sets `UIRequiresFullScreen`,
drops `supportsTablet`, moves the iOS minimum or re-adds the obsolete
`ios.enableSceneSupport` property.

## One-time machine setup

CocoaPods needs a UTF-8 locale, and the paths in this repository contain
spaces, so quote them:

```sh
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
```

The first `pod install` after the Stripe pin moved needed the spec repo
refreshed once (`pod install --repo-update`); later installs do not.

## Clean build, both apps

From the repository root:

```sh
pnpm install --frozen-lockfile

cd apps/player
npx expo prebuild --platform ios --no-install
(cd ios && pod install)
xcodebuild -workspace ios/Duna.xcworkspace -scheme Duna \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 ONLY_ACTIVE_ARCH=YES \
  -derivedDataPath /tmp/duna-dd-player build

cd ../pro
npx expo prebuild --platform ios --no-install
(cd ios && pod install)
xcodebuild -workspace ios/DunaPro.xcworkspace -scheme DunaPro \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 ONLY_ACTIVE_ARCH=YES \
  -derivedDataPath /tmp/duna-dd-pro build
```

Build the two apps one after the other, not in parallel: both run the
`expo-widgets` bundle step, which writes into the shared `expo-widgets`
package folder.

The Player build also compiles and embeds the watchOS app (`DunaWatch.app`)
and the widget extension (`ExpoWidgetsTarget.appex`).

Use `npx expo prebuild --platform ios --clean` after changing `app.json`,
a config plugin or a native dependency.

### Measured on this machine (27 November 2026, Apple silicon, warm CocoaPods and Hermes caches, cold Xcode derived data)

| Step                                   | Duna (with Watch) | Duna Pro |
| -------------------------------------- | ----------------- | -------- |
| `pnpm install --frozen-lockfile` (all) | 11 s              | (shared) |
| `expo prebuild --platform ios`         | 1 s               | 1 s      |
| `pod install`                          | 29 s              | 25 s     |
| `xcodebuild` Debug, simulator, arm64   | 100 s             | 72 s     |

The first `pod install` with a cold spec repo (`--repo-update`) took 267 s.
Expo SDK 58 ships precompiled Expo modules (`EXPO_USE_PRECOMPILED_MODULES`),
which is most of why the Xcode builds are short.

## Run in the simulator without credentials

Both apps have a credential-free preview mode: `EXPO_PUBLIC_DUNA_PREVIEW=true`
with `EXPO_PUBLIC_WORKOS_CLIENT_ID` unset. It shows a preview banner and
disables sign-in, payments and live operations.

Start one Metro bundler per app on its own port:

```sh
cd apps/player
env -u EXPO_PUBLIC_WORKOS_CLIENT_ID EXPO_PUBLIC_DUNA_PREVIEW=true npx expo start --port 8091

cd apps/pro
env -u EXPO_PUBLIC_WORKOS_CLIENT_ID EXPO_PUBLIC_DUNA_PREVIEW=true npx expo start --port 8092
```

Install the built apps and point each at its bundler:

```sh
DEVICE=<simulator UDID>   # xcrun simctl list devices available
xcrun simctl boot "$DEVICE"
xcrun simctl install "$DEVICE" /tmp/duna-dd-player/Build/Products/Debug-iphonesimulator/Duna.app
xcrun simctl install "$DEVICE" /tmp/duna-dd-pro/Build/Products/Debug-iphonesimulator/DunaPro.app
xcrun simctl spawn "$DEVICE" defaults write com.duna.player RCT_jsLocation "localhost:8091"
xcrun simctl spawn "$DEVICE" defaults write com.duna.pro RCT_jsLocation "localhost:8092"
xcrun simctl launch "$DEVICE" com.duna.player
xcrun simctl launch "$DEVICE" com.duna.pro
```

When you are done, remove the bundler override so the next run uses the
default port:

```sh
xcrun simctl spawn "$DEVICE" defaults delete com.duna.player RCT_jsLocation
xcrun simctl spawn "$DEVICE" defaults delete com.duna.pro RCT_jsLocation
```

The iPhone Duo simulator has two displays; take screenshots with
`xcrun simctl io "$DEVICE" screenshot --display=<id> out.png` (the command
lists the display IDs when you omit `--display`).

## Known build notes

- **Stripe.** `@stripe/stripe-react-native` 0.81.0 (Expo's SDK 58 pin)
  resolves the Stripe iOS SDK through Swift Package Manager only with dynamic
  frameworks. The Player sets the plugin's `disableSPM: true`, which keeps
  Stripe on CocoaPods with static linking. Stripe marks that option
  deprecated; versions past 0.83 remove it, and moving there means
  `useFrameworks: "dynamic"` for the whole Player app.
- **Mapbox.** `@rnmapbox/maps` 10.3.5 does not compile against React Native
  0.88 (`RNMBXMarkerViewComponentView.mm`); 10.3.19 does.
- **Expo Widgets.** SDK 58's `ExpoWidgets` pod adds a "Build ExpoWidgets
  Bundle" phase that builds the widget JavaScript bundle before "Prepare
  ExpoWidgets Resources" copies it, so a fresh checkout no longer needs a
  manual `build:bundle` step.
- **Paths with spaces.** SDK 58's generated bundle phase already quotes the
  React Native script path. The apps' compatibility plugins
  (`apps/player/plugins/with-ios-release-compatibility.js`,
  `apps/pro/plugins/with-ios-path-compatibility.js`) accept that form and
  only rewrite the older unquoted one.
- **CI.** CI cannot run simulators. It runs `pnpm verify:mobile-runtime` and
  the two JavaScript exports (`pnpm --filter @duna/player export`,
  `pnpm --filter @duna/pro export`).
